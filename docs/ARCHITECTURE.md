# Architecture decisions

The concise maintained reference is [TECHNICAL_GUIDE.md](TECHNICAL_GUIDE.md), with a flowchart, requirements matrix, module/function map and API table.

- **Model freedom:** the user explicitly requested AI-written contextual answers. This supersedes the PDF's R0 fixed business-fragment renderer. Live responses use authorized evidence, literal/reference checks, semantic review and one bounded revision. Review is not a proof of correctness; retained failures and reruns are listed in [VALIDATION.md](VALIDATION.md).
- **Degradation (1.7.4):** a rejected or unavailable model never ends a turn in an error. Rejected wording is replaced by the server's grounded template; an unreachable model, a spent evaluation budget or the per-conversation call ceiling hands observation to the scripted parser with a visible note. Gates are evaluated by the same server code in every mode.
- **Server-owned decisions (1.7.4):** verification lockout is counted per browser owner, so sessions, subject changes and logout cannot reset it. A verified policyholder's request about another person's records is refused without revoking their own grant; representative mode can be left by the caller identifying as the policyholder. Failed identity checks, candidate claim lists and recipient-change refusals are server wording that the model does not rewrite.
- **Four phases:** the server alone controls phase transitions and authorization. Claim hints may be remembered in VERIFY_ID; claim tools cannot run until a durable three-category grant is committed.
- **Separate domains:** support requests and email enquiries have their own references, revisions, timelines and idempotency keys. Waiting for a representative does not freeze the claim workflow. This follows the user's requested browser human-chat behavior instead of the PDF's original blocking handoff lifecycle. Legacy HANDOFF_PENDING sessions migrate on load.
- **Shared grant:** every panel reads the same owned session; there is no second account-panel login. Authentication epoch changes invalidate protected views, drafts and old operations. Foreground activity extends idle validity but cannot bypass absolute expiry.
- **Current action versus memory:** human_help is transient, not a remembered business intent. Continue with AI sends a server resume command; the selected channel survives a same-tab reload. Already collected identity can be verified during recovery, without fabricating a grant.
- **Consent:** a required post-process summary contains discussion, recorded result and next steps. The customer must be offered Send/Skip. Sending binds the exact draft/recipient/hash/epoch; new input pauses queued mail. A separately submitted insurer enquiry is its own explicit send operation.
- **Storage:** encrypted SQLite payloads, short transactions, turn leases, compare-and-swap versions and pre-dispatch checks protect local consistency. Browser principal + verified subject + case scope memory. Reference numbers alone never authorize private records.
- **Demo boundaries:** the six starter fixtures remain unchanged. No claim adjudication/payment/upload is performed. Human text is actually exchanged between two demo browser windows; emails and official email responses remain simulations. There is no production insurer integration.
